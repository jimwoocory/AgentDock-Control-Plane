# CP-15 执行合同

Outcome：在任务板定位用户指定任务关联的会话，分开显示任务状态、最近一轮事件和来源检查点，缺证据时不伪造实时进度。

用户已批准“任务ID→执行会话→Worker→当前步骤”的下一步。复用现有管理Agent字段、受限生命周期和20秒快照同步；模型/UI/MCP读取为范围内扩展，不增加执行控制、聊天正文采集或Core修改。Allowed Paths和Owner见任务板CP-15。

顺序：只读核对真实关联；干净独立分支/worktree；失败回归；共享关联模型/中文详情和正确MCP筛选；范围测试/构建；独立复审；提交/合入main并复验；原私有Site发布、正常所有者管理关联与真实MCP/UI读回。具体任务/会话ID只在私有.data证据保留。

Gate：active不能自动变Running；缺失、过期和冲突明确；原始ID和节点ID一致；任务/项目过滤无其他任务泄漏；最近一轮结束与业务完成分开；不改来源状态，不自动批准。全部实施、审查、main和线上验收完毕才标DONE。


Outcome：用户能够打开 localhost 控制台，看到家中 AgentDock 的真实任务、步骤、状态、历史，以及明确的数据来源与采集时间。

依赖：上游固定基线、pnpm 安装、可读 AgentDock 本地任务文件。源写操作为零。

顺序：安装与基线检查；实际格式审查；适配边界的失败测试；实现有大小与字段约束的只读采集与独立 SQLite 快照；认证 API；中文观察页面与项目关联；运行脚本；测试构建；独立代码审查；提交与 main 复验。

保留任务的实际外部 ID。步骤只是步骤，不宣称来源具备任意依赖 DAG。未报告 agent/heartbeat 的任务显示未知，不从标题猜测。源读取失败不能返回成功空集或删除旧历史。

Allowed Paths 见任务板；AgentDock Core、配置、任务文件、会话与现有项目均不得修改。真实数据不进入测试夹具或文档。
