# 完整 P0 设计与验收合同

用户已批准继续完成原始 P0，补齐 Task Graph 与 Agent 状态监控，不修改 AgentDock Core。本次扩展已运行的 P0-A，不另建产品或改变本机独立部署。

## 设计

采用独立 SQLite 管理层：本地 Epic/Feature/Task/Subtask 可创建、编辑；真实 AgentDock 任务/步骤从只读快照投影，并明确 origin。层级 parentId 与依赖 dependencies 是两类关系，图中分别连线。节点有项目、ID、标题、状态、优先级、负责人、Agent、验收条件。依赖必须引用存在节点且无环；父子必须同项目且无环；本地管理信息不反写源文件。持久化并记录管理变更历史。

不采用根据步骤顺序推测依赖，也不修改 Core 增加字段。来源未提供的关系只能人工在本地建立并标注。来源任务业务状态不可由控制台覆写；源缺失或采集失败保留最后事实并标记过期。

界面采用紧凑项目导航、图/树切换、节点详情编辑区、Agent 监控与历史区。图支持选择、缩放、滚动、项目与文字/状态筛选；依赖箭头指向后续节点，包含关系使用不同线型。50 个任务验收使用单独标注的测试数据库，不给真实来源注入示例任务。

Agent 观察必须来源于官方只读接口/工具或确实存在的本地运行记录，不从 task.active 推断 busy。单独存储身份、来源、状态、当前任务/动作、最近活动、真正心跳（若来源有）、最近采集、是否过期与事件。健康探测、进程存活、Agent工作状态三个概念分开；来源没有的字段显示未知。具体传输在能力调查后记录，不复制受保护凭据或更改 Core。

## 逐项验收

1. 创建项目：通过界面/API，重启后仍存在。
2. 创建任务树：Project → Epic → Feature → Task → Subtask，并编辑优先级/负责人/验收条件；重启仍存在。
3. 查看任务依赖：建立两项依赖，图与详情一致；自依赖、不存在引用与循环拒绝；源步骤不自动等同依赖。
4. 查看 Agent 状态：持续只读采集，有确实来源、采集时间和过期语义；状态与任务/动作按证据映射，未知不伪造；真实环境和受控状态夹具分别记录。
5. 查看执行历史：来源事件与本地管理变更清楚区分，Agent观察事件可追踪。
6. 多项目：USVDS2/BMAD/Toonflow/Google-TTS/Research Lab，单独50任务夹具中创建/筛选/依赖/选择互不串项目；浏览器实际验证。
7. 边界：来源任务文件 SHA-256 不变；Core 未改；未登录/跨工作区/跨源写拒绝；所有管理写只到控制台数据库。
8. 交付：独立分支提交、代码审查、main复验、生产构建、真实浏览器、本机可打开；没有验收的项不标完成。

原规格控制验收（运行时暂停/恢复、人工审批）属于 P1，当前仅本地优先级修改可在 P0验收。不得用修改 UI 状态模拟源任务暂停。
